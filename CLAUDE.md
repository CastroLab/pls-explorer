# pls-explorer (Claude notes)

## Environment

Use `/opt/anaconda3/envs/castrolab-dev/bin/python` — has sklearn 1.6.1,
plotly 6.5.0, scipy 1.15.3, plus `glom-explorer` editable-installed from
`~/code/glom-explorer`.

## Data

All data is loaded through `glom_explorer`. Do not re-bundle data here.

- Raw: `gx.load_processed_data()` → (odorants, low, high), shapes (59, 5),
  (59, 567), (59, 567). 567 gloms = 4 subjects concatenated.
- Clustered: `gx.load_clustered_variant('nonresponders_dropped')` → (low, high)
  with shape (59, 376). Column MultiIndex: gloms, subject, parent_cluster,
  subcluster, x, y. Row MultiIndex: odorant, odorant_cluster.

Default to `nonresponders_dropped` for PLS analyses (the public clean variant).

## Worktree pattern

The `pls_explorer/` package lives on `main`. Variants are git worktrees on
branches that customize only `configs/<name>.yaml` and (rarely) `runner.py`.
Do not duplicate core helpers across branches; PR them back into `main`.

## Conventions

- Library defaults: scikit-learn for PLS (continuity), plotly for viz.
  matplotlib/seaborn only for niche analyses or camera-ready static export.
- All result files keyed by variant + fit kind: `results/<variant>/{real,null1,null2}/`.
- Per-variant `report.md` is auto-generated by the runner; do not hand-edit.
- Family-stratified k-fold CV is the default (honest for chemical-class structure
  in 59 odorants). LOO is a sensitivity check, not the default.
